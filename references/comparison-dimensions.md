# 比较维度与打分口径（A 流程）

> **用途**：A 流程的打分口径——维度定义、锚点分档、覆盖率与最大可达分、硬约束过滤、警示降级与平局。
>
> **何时读**：做 A 类候选对比、需要给出"总分 X.XX／满 Y.YY（覆盖率 Z%）"时。
>
> **边界**：只给打分口径，不改判定阈值；价格分子与分母一律以 `SKILL.md` 2.3 为唯一来源，本节只引用不复述；锚点为经验设定、未经实证校准。
>
> **最后核验日**：2026-11-09（规则文件，随版本修订；无外部事实项）

## 默认维度（可扩展）

| 维度 | 口径 | 数据来源优先级 |
|---|---|---|
| 价格 | **全口径月支出**（房租＋电＋水＋燃气＋宽带＋物业/卫生公摊＋一次性摊销＋通勤票价，口径见 `SKILL.md` 2.3）；房租须单列，便于与挂牌价对照 | 链接 / 文本 / 截图 / 手动填表 |
| 通勤时长 | 单程（至实习单位/公司），含换乘 | 地图估算 → 看房实测修正 |
| 面积 | 建筑面积/使用面积需标注 | 链接 / 文本 |
| 楼层朝向 | 楼层、朝向、有无电梯 | 链接 / 文本 |
| 租约条款 | 租期、押金、解约/转租、违约金 | 文本 / 合同 / 看房确认 |

用户可增删维度；删除后口径同步调整，输出注明变更。

## 口径细则（v1.4.0 新增）

- **通勤"站数 vs 时长"**：输入为地铁/公交站数时，先按站序相对打分，并在输出声明"时长需地图工具核实（早高峰每站约 3–5 分钟为经验值，不作评分依据）"；不得把站数直接当分钟数入表。
- **跨城市候选**：不同城市的候选不进入同一张打分表——通勤基准、收入水平、补贴政策均不同，加权总分无意义；应分城市各自过风险层并算月度净成本（租金 − 当地补贴/人才公寓折扣 + 通勤成本），再比较。
- **同维度多口径**：面积须标注建筑面积/使用面积；租金须标注是否含物业/网费；口径不同的候选先统一口径再打分，无法统一时在对比表注明。
- **单套候选（v1.7.0 回归运行 R-H4 所补）**：只有 1 套时**不出打分表**——没有对比对象就不存在"总分"，只走风险层＋预算纪律检查，并在输出说明"补齐候选后再打分"；不得为单套构造绝对分数供用户误读。
- **混合口径候选集**：整租与合租可在同一张表内比较，但面积必须分档取值（整租按整套、合租按个人卧室），并在表下声明两者口径不同、可比性受限（见回归记录 R-P4）。

## 打分（v1.7.0 起：锚点表优先于临场判断）

> **锚点性质声明（v2.3.0）**：本节的档位阈值与 `renter-profile.md` 的默认权重均为作者基于实习/职场新人画像的**经验设定，未经实证校准**（无租客满意度或成交数据对照）；不构成行业标准或法律标准，具体数值不得对外引用为"行业惯例"。用户可按需覆盖，覆盖后输出注明"锚点已被用户覆盖"。

旧版只规定"每维度 1–5 分，给出依据"，未规定原始值→分数的映射，导致"可复算"只在加权求和一步成立，打分一步仍是黑箱（见 failures.md F6 的残留部分）。现给出可推导锚点：

### 分档锚点

| 维度 | 原始量 | 锚点（分档取**左闭右开**，命中即得分，不再凭印象调） |
|---|---|---|
| 价格（用户明示预算上限时） | P ＝ **全口径月支出** ÷ **房租上限**（房租上限＝预算 − 水电燃气/宽带/物业公摊/一次性摊销/通勤票价，由 `SKILL.md` 2.3 推出） | ≤0.70 → 5；0.70–0.85 → 4；0.85–1.00 → 3；1.00–1.15 → 2；>1.15 → 1 |
| 价格（未明示预算上限时） | P ＝ **全口径月支出** ÷ 月收入 | ≤0.25 → 5；0.25–0.35 → 4；0.35–0.45 → 3；0.45–0.60 → 2；>0.60 → 1 |
| 通勤 | 单程分钟（门到门，含换乘候车） | ≤15 → 5；15–25 → 4；25–35 → 3；35–45 → 2；>45 → 1 |
| 通勤（输入为站数时） | 站数（不得当分钟用） | 候选集内按站序等距映射：最优＝5、最差＝1，中间按 `5 − 4×序号差 ÷ (候选数−1)` 取值后四舍五入到整数；**序号差＝该候选按站数升序的排名减 1（最优＝0、最差＝候选数−1），不是"与最优的站数差"**；并注明"分钟待地图核实" |
| 面积 | 整租/一居室按套内或使用面积；合租按**个人卧室**面积 | 整租：≥45 → 5；35–45 → 4；25–35 → 3；15–25 → 2；<15 → 1。合租（单间）：≥15 → 5；12–15 → 4；9–12 → 3；7–9 → 2；<7 → 1 |
| 楼层朝向 | 记号累加，基线 3 分 | 有电梯 或 楼层≤3 ＋1；朝南或南北通透 ＋1；顶层／底楼潮湿／西晒／无采光／无电梯且≥4 层 各 −1；结果夹到 1–5 |
| 租约条款 | 四项合规记号：①押付方式合规（押一付一/押一付三，非超 3 个月预付）②书面合同③提前解约条款明确④押金数额/返还时间/扣减情形写入合同 | 得分 ＝ 1 ＋ 满足项数 − 不满足项数（夹到 1–5）；未提供的项记"待核"，不计满足也不计不满足。**四项全部待核 → 该维度记"待补充"、不入分**（与楼层朝向同规则）；有 1–3 项待核时，输出须注明"租约维度仅 N/4 项已确认，得分可能高估或低估" |

- 用户可增删维度或改写阈值；改写后按用户口径重算并在输出注明"锚点已被用户覆盖"。
- **价格口径不得混用（v1.7.0 定稿，v2.2.0 单源化，v2.5.0 改分子）**：同一维度出现两个分母，会让同一输入推出两种分数，破坏确定性。**分子与分母的选择一律以 `SKILL.md` 2.3"预算 X 的固定映射"为唯一来源**（有明示预算上限 → 分子取全口径月支出、分母取房租上限；无明示预算上限 → 分母取月收入；全口径月支出缺项时该维度记"待补充"、不入分），本节只引用不复述。**"月租 ≤ 月收入 30%"属预算纪律，走 `legal-risk-notes.md` 与风险层的提示级判定，不作为打分分母**——否则实习画像下几乎所有候选会同时命中最低档，价格维度失去区分度却被总分掩盖。
- **"是否明示预算上限"先判定**：分母选择先于打分，选择不同则结果不同；判定分支一律按 `SKILL.md` 2.3 执行，本节不另立规则。
- **饱和声明（强制）**：某一维度在候选集内所有成员命中同一档位时，输出须写明"该维度已饱和、无区分度"，并说明是超预算饱和（全部最低档）还是信息缺失饱和，不得让读者误读为"该维度打平"。**该维度不得被静默剔除**；是否剔除重算须给用户显式选项——"价格无区分度，是否剔除价格重算？"，用户未回答前保留原权重并注明。
- 每维度 1–5 分，**逐维度写出命中的锚点区间**（如"价格 2800÷预算上限 3000＝0.93 → 落在 0.85–1.00 档 → 3 分"，须与 2.3 选定的分母一致），使第三方可仅凭包内规则复算。
- **租约维度的"未知"与"不合规"要分开（v1.7.3）**：v1.7.0 只有"1＋满足项数"，没有减分项，导致"确认不满足"与"信息缺失"都停在基线 1 分，无法区分。现改为：确认不满足项每项 −1，未知项不加不减；四项全未知则该维度不入分（避免把"没问到"当成"条款差"）。
- **维度内确认度（v1.7.3）**：覆盖率回答的是"缺了哪些**维度**"，不回答"维度内确认了多少项"。故租约类多记号维度在 1–3 项待核时，必须在表下写明"N/4 项已确认"；覆盖率仍按该维度整体计入（有观测即参与），但不得据此声称该维度"信息完整"。
- **通勤分数的可移植性（v1.7.3）**：站数等距映射是**候选集内**的序数映射——同一套房在不同候选集中的得分会变（加入一套更远的候选，其他套的站序分会上升）。故 **分数只在同一候选集内可比**；候选集增删后必须整集重算，不得与历史记录或其他候选集的分数直接比较。

### 覆盖率与可比性（防"缺项压低总分"的系统偏差）

"缺数据维度不参与加权且不重新归一化"会同时带来一个副作用：**信息缺失越多的候选总分天然越低**，且两个候选缺失项不同时时不可比。故强制：

- 每套候选在**对比表后统一标注**（不塞进表头，避免 SKILL.md 4.2 固定表头变形）：**维度覆盖率 ＝ 参与加权维度的权重之和**，并标注 **最大可达分 ＝ 5 × 覆盖率**；
- 输出格式：`总分 X.XX／满 Y.YY（覆盖率 Z%）`；
- 跨候选比较前必须先检查覆盖率是否一致：一致→直接比总分；不一致→改比**归一化分 ＝ 总分 ÷ 覆盖率**，并同时给出两者、说明采用了哪一个；
- **归一化分仅作参考、不得单独用于排序**：它会把缺项候选的剩余维度放大（覆盖率 0.80、总分 3.2 → 归一 4.00，可能反超覆盖率 0.95、总分 3.5 → 归一 3.68 的候选）；缺项维度必须单列，排序须同时满足"归一化分＋缺项说明"两个条件；
- 因缺项导致的分差不写进结论句（不得说"某套更好，因为它分数高"而实际只是信息少）。

### 硬约束、降级、平局与敏感性（v1.8.1）

**硬约束过滤（先于打分）**：用户给出可判定的硬上限/必须项时，先筛后排——月租上限、单程分钟上限、最短租期、必须可转租/短租、必须整租/合租。不满足者标"硬约束出局"并写明违反项，**不算总分、不进主排序**；全部出局时输出"无满足硬约束的候选"＋放宽建议，不硬推。对比表中出局者的"总分"列固定填**"出局（未算分）"**（不填 0、"—"或留空），违反项在表下单列。"月租 ≤ 收入 30%"是提示级预算纪律，**不是**硬约束；只有用户明示上限才硬筛。

**警示降级（把 3.1 的"降级"说清）**：警示级**不扣维度分**（风险不参与打分），但在推荐排序时**置于无警示候选之后**；若全部候选都有警示，输出"相对最优＋风险清单"，不得写"推荐"；否决级直接出局，不参与排序。**分差 >0.20 时必须提示用户权衡**（"无警示候选总分低 X 分，但绕开了〔风险〕；若该风险你可控，前者更优"），不得只给一个排序。

**这是排序层规则，不是得分层规则（v2.2.0 明确）**：警示候选的总分照常计算并完整展示，排序键为「警示层（无警示＝0／警示＝1）→ 总分降序」，因此允许出现"分高但排后"。凡出现这种情形，对比表下必须注明"X 总分更高，因警示降级排后，原因是〔具体风险项〕"，不得静默调整分数让排序与总分一致。

示例：A 总分 85 但押金条款命中警示、B 总分 80 无警示 → 推荐序为 B、A，并注"A 85 分高于 B，但因其〔押金扣减无依据〕警示降级排后；若你能接受该风险，A 在价格/通勤上更优"。

**平局处理**：总分差 ≤0.10 视为平局，依次比较——月租更低 → 单程通勤更短 → 覆盖率更高；仍相同则并列，写"无实质差异，按预算/通勤偏好选"，不制造假排序。

**敏感性提示**：前两名差 ≤0.20，或任一核心权重 ±0.05 会改变排序时，标"**排序不稳健**"，并列两种权重下的排序与结论；不得只给单一推荐。示例："B 领先 A 0.15；通勤权重由 0.30 降到 0.25 后 A 反超 → 排序不稳健，若你更看重通勤选 B，更看重租金选 A。"

**权重来源**：默认表或用户明示调整（见 `renter-profile.md` 权重推导）；未明示不得自动改权重；用户直接给权重时**先归一化到 1.00 → 再算 → 再夹到 1–5**，并注明（与 `renter-profile.md` 同一顺序，不再分叉）。

### 与历史记录的冲突处理

v1.3.0 的 `evals/records.md` T1 与独立复测 R-T1 采用判断式打分（价格 2800→3、3200→2、2500→5；通勤 1 站→5、3 站→3、5 站→2；面积 40→3、50→5、30→2；租约均 3；楼层缺省）。按本锚点表复算，**五个维度中有四个格的取值发生变化**，不只是通勤：

| 维度 | 历史（判断式） | 锚点表推导 | 变化原因 |
|---|---|---|---|
| 价格 | A 3 / B 2 / C 5 | A 1 / B 1 / C 1 | 无明示预算 → 分母为月收入；0.83–1.07 全部 >0.60 → 最低档，**价格维度饱和** |
| 通勤 | A 3 / B 5 / C 2 | A 3 / B 5 / C 1 | 站数按站序等距映射，5 站为候选集最差 → 1 |
| 面积 | A 3 / B 5 / C 2 | A 4 / B 5 / C 3 | 40㎡ 落 35–45 档、30㎡ 落 25–35 档 |
| 楼层朝向 | 缺省（—） | 缺省（—） | 未提供 → 缺省、不加权 |
| 租约条款 | 三套均 3 | 三套均 2 | 仅"押付方式合规"一项确认，其余三项待核 → 1＋1 |

结果：历史 2.85/3.45/3.00 → 锚点推导 2.20/2.95/1.45（覆盖率均 0.95、满 4.75），排序由 B>C>A 变为 **B>A>C**。**历史记录原文保留不改**（照录原则），新口径下的复算过程与结论见 `evals/records-v1.7.0-回归.md` R-T1。

> v1.7.3 复核：租约公式改为"1＋满足−不满足、全未知不入分"，但 T1 与 P4 的租约均为"1 项满足、0 项不满足、3 项待核"，得分仍为 2；价格/通勤/面积/楼层口径未动，故 25 条既有记录的分数与判定不变（工具层复核见 `evals/records-v1.7.3-结构自检.md`）。

> **v2.5.0 口径变更（分子改为全口径月支出，分母为房租上限/月收入）**：这是**判定口径变更**，不是表述调整，故：①历史 25 条记录**原文保留不改**（照录原则），其价格分按旧"月租÷预算"口径得出，**不得与新口径分数混比**；②同一候选集在新旧口径下结论不同的，以新口径为准并在输出注明"按 v2.5.0 全口径口径"；③未提供水电燃气/宽带/物业/通勤任一项时，按 `SKILL.md` 2.3 只给公式与缺项清单，**价格维度记"待补充"、不入分**，不得用"月租"冒充全口径。

## 风险层

风险不参与打分：否决 → 出局；警示 → 不扣分、推荐序后置并标红（定义见上节"警示降级"）；提示 → 弱标。细则见 `legal-risk-notes.md`。
