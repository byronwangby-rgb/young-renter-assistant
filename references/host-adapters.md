# 宿主适配对照表（按不同 AI 助手特性落地）

> **用途**：`SKILL.md` 第 7 节「宿主移植」的展开——四类宿主（豆包客户端／Claude Code 与 Claude.ai／其他 agent 客户端／纯本地无网模型）的"能力×具备×降级"矩阵与配置。
>
> **何时读**：换宿主、或宿主缺检索/缺提问组件/上下文短时，需要决定"哪条能力降级成什么"。
>
> **边界**：换宿主只改配置、不改规则；**不派生第二份 SKILL.md**；输出档位、免责声明、押金五关、数值效力、外地不保真五条不变式与宿主能力无关。
>
> **最后核验日**：2026-11-09（规则文件；各宿主实际能力以第一节"先探测"的实测结果为准）

本文件是 `SKILL.md` 第 7 节「宿主移植」的展开：同一套规则，在不同 AI 助手上按"有则用、无则降级"配置。**不派生多份 SKILL.md**——同一规则写两处必然漂移，宿主差异只在本表里表达。

## 一、先探测，再适配

启动时按顺序问三个问题，答案决定后面走哪一列：

1. **能不能联网？** 试一次现查（如查一条法条原文）。查到 → L1 可用；报错／无工具 → 无网档。
2. **有没有交互式提问组件？** 有专用提问工具（如豆包的 `interaction_ask`）→ 组件档；只能发文本 → 文本档。
3. **能不能交付文件？** 有文件/附件交付能力 → 交付档；只能输出文本 → 文本档。

## 二、四类宿主 × 六项能力

| 能力 | 豆包客户端 | Claude Code / Claude.ai | 其他 agent 客户端（Qoder、WorkBuddy 等） | 纯本地模型（无网） |
|---|---|---|---|---|
| 联网检索 | L1 现查＋来源＋检索日 | Bash/WebFetch 可查，同 L1 口径 | 探测后定：能查即 L1，不能查即无网档 | 一律"未查到＋查询路径＋检索日"；内置杭州值标"内置值、未核实" |
| 交互式提问 | 用提问组件，一次 ≤4 字段 | 无组件 → 编号列表提问，规则不变（每轮 1 次、≤4 字段，不连环追问） | 有则用、无则文本 | 文本提问，建议一次只问 2 个字段，减少来回 |
| 图表渲染 | 可按 4.2 可视化三档 | 终端/对话多数不支持 → 一律 Markdown 表格 | 探测，不支持即表格 | 一律 Markdown 表格 |
| 文件交付 | 直接交付 DOCX／表格文件 | 写工作目录并给绝对路径；有 artifacts 时用 artifacts | 写工作目录＋绝对路径 | 只输出 Markdown 单页，用户自行另存 |
| 脚本执行 | 可用（自检脚本不在公开版，跳过） | Bash 可用；本包无脚本依赖，仅用于辅助计算 | 视权限而定；本包主流程不需要 | 不可用，全部手算或心算，并在输出标注"手算" |
| skill 自动加载 | 装入技能目录，按 name/description 触发 | `.claude/skills/` 或项目内自动扫描；否则作为首条系统规则／AGENTS 载入 | 视客户端而定，多数需手动指定入口 | 人工把 `SKILL.md` 贴为首条指令；`references/` 路径按 `SKILL.md` 所在目录解析 |

## 三、上下文短（约 8k tokens 以下）时的读法

长上下文宿主可以一次读多份 references；上下文紧张的宿主按场景**只读必需的两三份**，不要预读全部：

- A 流程：`comparison-dimensions.md` + `legal-risk-notes.md` + `workbench/风险点核验表.md`
- B 流程：`search-kit.md` + `market-reference.md`
- C 流程：`renewal-negotiation.md` + `market-reference.md`
- D 流程：`contract-review.md` + `legal-risk-notes.md` + `workbench/编号映射.md`

读不到全部时，输出末尾写明"本次仅依据 X、Y 判定，Z 未加载"，不要把没读的当读过。

## 四、换宿主时必须保留的三条不变式

1. **输出两档不变**：重大决策档仍走七段，咨询档仍写结论＋依据＋风险边界；不因宿主弱就退化成"随便说说"。
2. **免责声明与会话首次事前告知不变**：组件缺失不构成省略理由。
3. **判定与宿主无关**：押金五关、数值三级效力、外地不保真、硬约束先行，均不随宿主变化。

## 五、写宿主专属内容时的边界

- 只写"能力差异怎么降级"，不写"某个宿主的品牌话术"。用户换宿主时不需要重学规则。
- 不新增第二份 SKILL.md、不复制 references。宿主差异只在本表追加一列。
- 宿主能力探测结果不确定时，按**较弱一档**执行，并在输出标注"按降级档执行"。
